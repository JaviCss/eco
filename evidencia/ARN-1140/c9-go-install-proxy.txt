# ARN-1140 · criterio 9: go install github.com/JaviCss/eco/cmd/eco@v0.1.0 por GOPROXY=file://
# fecha: 2026-10-07T15:19:35.3918148-03:00
# go: go version go1.26.1 windows/amd64
# exit de la corrida: 0

## Tres cosas que hubo que arreglar antes de que la corrida significara algo.
Cada una hacia que la corridaDijera 'verde' sin probar nada. Se dejan escritas porque
son la forma en que esta prueba puede Mentir.

1. GOPRIVATE no va. GOPRIVATE implica GONOPROXY, que saltea el GOPROXY y hace
   git ls-remote contra github. Primer intento:
     go: github.com/JaviCss/eco/cmd/eco@v0.1.0: loading deprecation for github.com/JaviCss/eco:
     git ls-remote -q --end-of-options https://github.com/JaviCss/eco: exit status 128:
     remote: Repository not found.        (pegado de la corrida fallida)
   Con GOSUMDB=off y GOFLAGS=-mod=mod alcanza; el zip no se verifica contra la suma.

2. La cache de modulos tenia un eco@v0.1.0 de la sonda de diseno (79615 bytes), y go
   instalaba ESE sin volver al proxy: salia 0, pero el binario no tenia --version.
   Se borro la entrada de la cache de eco antes de instalar, y despues se comparo el
   hash del zip de la cache contra el del proxy (abajo: True).

3. La cache del filesystem de Go (go clean -cache) tenia la lectura del directorio
   del path del modulo desde la sonda, asi que el compilador no VIA el version.go recien
   extraido: 'undefined: versionLine' con el archivo sitting en el directorio.
   Con la cache limpia compila. Que un 'undefined' con el archivo al lado sea un bug de
   cache y no del codigo es lo que hace esta pruebaparable de nuevo.

### lo que se ve aqui, y es un hecho sobre el instrumento:
El binario instalado por el proxy dice 'eco v0.1.0' y NO trae vcs.revision: el zip
del modulo no lleva .git, asi que el go tool no tiene VCS que estampar. El binario de
dist/ si lo trae, porque se compilo desde el arbol. El numero que comparten las dos
rutas es el Main.Version (v0.1.0), no el vcs.revision. Queda declarado, no resuelto:
la card (criterio 2) pide 'la misma vcs.revision' en las dos rutas y eso no lo da el
instrumento: vcs.revision solo existe cuando el build ve un arbol de control de versiones.
